# 日本 1:1 Minecraft ワールド（1 ブロック = 1 m）

[English](README.md) | **日本語**

静岡県・山梨県と、東京都・神奈川県・愛知県東部などを、国土地理院の 1 m 標高データと道路・鉄道・建物・植生のオープンデータから
**1 ブロック = 1 m** で再現した **Minecraft Java Edition 1.21.11** 用のワールドです。

- 範囲: 北緯 34〜36°・東経 137〜140°（東西 約 270 km × 南北 約 220 km、海を含む）
- 全体 約 1 TB。**遊びたい範囲（約 10 km 四方のタイル）だけを選んでダウンロード**できます
- 🗾 **[タイル選択ページ](https://ikuto32.github.io/japan-1to1-minecraft/tiles.html)** ・ 🧭 **[移動コマンド作成ページ](https://ikuto32.github.io/japan-1to1-minecraft/teleport.html)**

| 土地利用 | 水田・畑・茶畑（畝）・果樹園・温室・ソーラーパネル・空港（滑走路の白線）・港・ダム・公園・墓地・駐車場など |

## 必要なもの

- **Minecraft Java Edition 1.21.11**（このバージョン専用です。ほかのバージョンでは開けないか、地形の高さが壊れます）
- ディスク: タイル 1 枚あたり展開後 約 0.03〜1.7 GB（海のタイルは小さい）。全体を入れると約 970 GB
- メモリ 4 GB 以上を Minecraft に割り当て推奨。ワールドの高さが通常の 10 倍あるので、描画距離は 8〜12 チャンク程度がおすすめです

## ダウンロードとインストール

1. **[タイル選択ページ](https://ikuto32.github.io/japan-1to1-minecraft/tiles.html)** で、地図の四角（タイル）をクリックして遊びたい範囲を選びます
   （「よく使う範囲」のボタンや、Shift + ドラッグでの範囲選択もできます）。
2. ページに表示されたコマンドをコピーして実行します。
   - **Windows**: スタートメニューで「PowerShell」または「コマンドプロンプト」を開いて貼り付け
   - **macOS / Linux**: ターミナルに貼り付け

   ```powershell
   curl.exe -L -o download.ps1 https://github.com/ikuto32/japan-1to1-minecraft/releases/download/v1.0.0/download.ps1
   powershell -ExecutionPolicy Bypass -File download.ps1 -Tiles x-20480_z112640,x-10240_z112640
   ```
   ```bash
   curl -LO https://github.com/ikuto32/japan-1to1-minecraft/releases/download/v1.0.0/download.sh
   bash download.sh x-20480_z112640 x-10240_z112640
   ```
   Minecraft の `saves` フォルダ（Windows は `%APPDATA%\.minecraft\saves`）に `japan_dem_1m` フォルダができます。
   保存先を変えるときは `-Dest D:\minecraft\saves`（macOS/Linux は `-d フォルダ`）を付けます。
3. Minecraft 1.21.11 を起動し、シングルプレイで「日本 1m DEM（静岡・山梨とその周辺）」を開きます。富士山頂にスポーンします。

- **あとからタイルを足す**: 同じコマンドに新しいタイルを入れて実行します。取得済みのタイルは飛ばし、`level.dat`（プレイヤーの位置・持ち物）は上書きしません。
- 必ず一緒に入る `japan1m_base.zip`（約 15 MB）には、ワールドの設定・データパックと富士山頂のまわり約 1.5 km 四方が入っています。
  富士山のタイルを選ばなくてもスポーン地点には地面があり、あとから富士山のタイルを足してもスポーン地点に建てたものは消えません。
- スクリプトはダウンロードした zip の SHA-256 を確認し、途中で止まっても再実行で続きから取得します。
- **手動でダウンロードする場合**: [リリースページ](https://github.com/ikuto32/japan-1to1-minecraft/releases/latest) から `japan1m_base.zip` と必要なタイルの zip を取得し、
  `saves` の中に `japan_dem_1m` フォルダを作ってすべて展開します（タイルの zip の中身は `region/r.*.mca`）。
- タイルの ID は、そのタイルの北西の角の Minecraft 座標です（例: `x-10240_z112640` は X -10240〜0、Z 112640〜122880）。

## 遊び方

### 座標

| | |
|---|---|
| 向き | X が東、Z が南、1 ブロック = 1 m（北緯 36°・東経 138.5° が X = 0, Z = 0） |
| 高さ | 標高 h m の地面のブロックは Y = -1760 + h。海面は Y -1760、富士山頂は Y 2015 |
| 投影法 | ランベルト正角円錐図法（GRS80、標準緯線 30°N・40°N、原点 36°N 138.5°E） |

緯度経度とゲームの座標の変換は **[移動コマンド作成ページ](https://ikuto32.github.io/japan-1to1-minecraft/teleport.html)** で行えます。
地図をクリックするか地名を検索すると、`/function jp:goto {x:…,z:…}`（地表に着地）や `/tp @s X Y Z` を作ります。
ゲームの F3 画面の座標を入れると、地図上の位置と緯度経度を表示します。

### ゲーム内のメニュー（データパック）

チャットで **`/function jp:menu`** と入力すると、クリックで使えるメニューが出ます（日本語 / English 切り替え可）。

| コマンド | 内容 |
|---|---|
| `/function jp:menu` | メニュー |
| `/function jp:places` | 主要地点 44 か所（富士山頂・五合目・東京駅・東京タワー・スカイツリー・静岡駅・甲府駅・江の島・箱根・伊豆など）へ移動 |
| `/function jp:goto {x:-10094,z:113663}` | 指定した X・Z の一番上のブロックに着地 |
| `/function jp:surface` | 真下の一番上のブロックに降りる |
| `/function jp:hud` | 画面下に現在地の標高と緯度・経度（約 30 m の精度）を表示（ON/OFF） |
| `/function jp:nv` | 夜間視覚（ON/OFF） |
| `/function jp:day` / `jp:time_normal` | 昼・晴れに固定 / 元に戻す |
| `/function jp:step` | 1 ブロックの段差をジャンプせずに上る（ON/OFF） |
| `/function jp:fall` | 落下ダメージ（ON/OFF） |
| `/function jp:elytra` | エリトラとロケット花火 64 個（遠くへ移動するとき便利） |

ダウンロードしていないタイルへ移動しようとすると、データパックのコマンドは移動を取りやめるか、スポーン地点（富士山頂）に戻します。

### ヒント

- すべてのチャンクに照明（空の明るさ）を計算済みで入れてあるので、初めて読み込むときにゲームが照明を計算し直すことはありません。
- 富士山頂付近（標高約 2,950 m 以上）は雪、森林限界（約 2,500 m）より上は岩と砂礫です。
- 水田は水を張った状態で、苗の列として海草（seagrass）を使っています。

## 既知の制限

- 建物の内部は各階の床と出入口だけの簡単なつくりです（間仕切り・階段はありません）。PLATEAU の無い市町村の建物の高さは推定です。
- OpenStreetMap に無い道路・鉄道は描かれません。道路の幅は、基盤地図情報の道路縁が無い所では道路の種類の標準幅です。
- 吊り橋やトラス橋の上部構造、複雑な立体交差は簡略化しています。海底トンネルは描きません。高架の高さ・地下鉄の深さは
  OSM の `layer`（例: layer -3 ≈ 地下 24 m）から決めたもので、実測値ではありません。
- 海底地形の細かさは ETOPO 2022 の格子（約 460 m）程度です。約 270 m より深い所は平らです。港・運河の深さは岸壁から決めた推定で、海図の水深ではありません。
- 植生図・土地被覆図の作成時期と現在の土地利用が違う所があります。
- 樹木の高さを点群から求めたのは静岡県内だけです（他の地域は植生ごとの標準的な高さ）。

## 自分でワールドを作る（開発者向け）

Rust 製のツール `jpdem` で、国土地理院の標高データとオープンデータからワールドを作ります。データの置き方・各手順・処理時間・
検証方法・地域の追加方法は **[BUILDING.ja.md](BUILDING.ja.md)** にまとめています。

```powershell
cargo build --release
pwsh -File build_all.ps1          # 標高 → 高さマップ → 道路・建物・植生 → ワールド（32 スレッドで約 2〜3 時間）
python tools/gen_datapack.py      # ゲーム内ツールのデータパック（assets/datapacks/japan_tools）
```

植生・土地利用とブロックの対応は `config/landcover_map.csv` で調整できます（BUILDING.ja.md §11.2）。

## 配布物の作り方（リリース担当者向け）

1. `python tools/set_repo.py OWNER/REPO` で、`release.json` とこの README のリンクを自分のリポジトリに合わせます（タグは `release.json` の `tag`）。
   続けて `python tools/gen_datapack.py` を実行すると、ゲーム内メニューにウェブページへのリンクが入ります。
2. `python tools/package_release.py --out D:\release` で、タイルごとの zip（各 2 GiB 未満）・`japan1m_base.zip`・マニフェスト
   （`tiles.tsv` / `tiles.json`）・ダウンロード用スクリプトを作ります（合計約 355 GB）。`docs/data/tiles.json` も更新されます。
   ゲームで遊んだワールドを配布したくない場合は `--from-build` を付けると、タイルごとに作り直してから zip にします
   （32 スレッドで約 2 時間。同時に作るタイル 1 つにつきメモリを約 6 GB 使うので、足りなければ `--jobs` で減らします）。
   途中で止まっても同じコマンドで続きから再開できます。リポジトリ名やタグを変えたときも再実行すれば、
   タイルの zip はそのままで base の zip・マニフェスト・スクリプトだけを作り直します。
3. 出力フォルダの `upload.ps1`（GitHub CLI の `gh release create` / `gh release upload`）で GitHub Releases に公開します。
4. リポジトリの設定で GitHub Pages を `main` ブランチの `/docs` フォルダから公開すると、タイル選択ページと移動コマンド作成ページが使えます。
